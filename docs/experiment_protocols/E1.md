# E1 算子异质性 pilot 正式协议（冻结版 1.0）

## 1. 状态、范围与科学假设

本协议对应 `configs/e1/pilot.yaml` 与 `src/tc_mo_me/e1_protocol.py`。协议、配置和计划生成规则必须先于任何真实 E1 Episode 冻结。**当前没有启动真实 E1，没有调用付费模型 API，没有产生 child 成绩，也没有进行任何统计分析。**

E1 的科学问题是：在同一任务、环境 seed、模型和逐 Episode 预算下，三类受控算子产生的 child 相对于其主父代是否呈现可观察、可估计且可复现的异质性。对算子 \(o\in\{O1,O2,O3\}\)，块 \(b\) 的主要配对量为

\[
\Delta Q_{o,b}=Q_{o,b}^{child}-Q_{b}^{primary\ parent},
\]

其中 \(Q\) 是官方评价中非 no-op 目标测试的通过比例。每个算子的主要零假设为 16 个块的 \(\Delta Q\) 均值为零，备择为双侧非零。不预设 O1、O2 或 O3 谁更优，不把单次正向结果解释为搜索有效性或元演化收益。

本 pilot 用于检查算子区分、流程可观察性、状态反泄漏、成本记录和后续估计流程。112 Episode 是固定的小型异质性检查样本，**不是确认性样本量**，不承担 RQ1/RQ2 的正式效果证明，不启动 RQ3，也不实现双层元演化。稳定候选门槛只是进入后续独立验证的筛选规则，不是确认性结论。

数据划分严格固定为：

- `train`：仅用于本 pilot 的任务选择、运行和诊断；
- `dev`：本阶段完全保留，不选题、不调参、不查看结果，供后续另行批准的独立验证；
- 不使用任何 Agent 或 child 历史成绩选题，不把 ground-truth solution、评价代码、答案或原始任务数据复制进仓库。

## 3. Episode、块与算子规格

### 3.1 112 Episode 分解

8 个任务按 `task_id` 字典序排列，每任务依次使用环境 seed `[100, 200]`，形成 \(8\times2=16\) 个块，编号 `b=0..15`。每块固定 7 个 Episode：

- 4 个初始父代 control，共 \(16\times4=64\) Episode；
- O1、O2、O3 各 1 个 child，共 \(16\times3=48\) Episode；
- 合计 \(64+48=112\) Episode，即 \(16\times7\)。

父代 Episode ID 为 `e1-b{b:02d}-p{i}`，child ID 为 `e1-b{b:02d}-o1|o2|o3`。四个父代依次为：

| 索引 | Genome ID | 内容 SHA-256 |
|---|---|---|
| 0 | `g0_baseline` | `b201f8e5d53aefd06e416a3fc81dea4bef1bc32bc59452bf7b5e2404e88f5613` |
| 1 | `g1_planner` | `b834b274ea07e77e0c82cac7dc0e0d4f9bbdb9e4811d246111ffb369739ca6e6` |
| 2 | `g2_verifier` | `e22c54b12d7528fbe8b7b13e316aa569560452fd71e0ae5850185ad32b553b4c` |
| 3 | `g3_workflow` | `c28ea0f9563aec42cd27e98193c3cc20abd2cf83699ad04c883a6825d8eef78b` |

构建计划必须从 `configs/e1/genomes` 重新读取并用项目 `genome_hash` 重算；文件缺失、额外 Genome JSON 或 hash 不符均拒绝构建。身份元数据、任务 outcome 和历史成绩不进入 Genome 内容 hash。

### 3.2 主父代与 O1/O2/O3

令 \(P=b\bmod4\)，三个 child 的主父代均为 \(P\)。主父代索引在全部 child 中各出现 12 次。

- **O1（单父代局部内容变异）**：目标按 `system_prompt → planning_policy → code_generation_policy → verification_policy` 循环，目标为 `O1_COMPONENTS[b mod 4]`。只允许修改目标组件，`parent_indices=[P]`，五个 `component_sources` 均指向主父代 Genome。
- **O2（单父代工作流结构变换）**：操作按 `insert → delete → replace → reorder` 循环，操作为 `O2_OPERATIONS[b mod 4]`。`parent_indices=[P]`，五个组件来源均为主父代；实际生成仍须通过现有 O2 的结构和授权校验。
- **O3（三父代组件重组）**：`parent_indices=[P,D1,D2]`，其中 `D1=(b+1) mod 4`、`D2=(b+2) mod 4`。两个 donor 索引在 16 块中各出现 8 次。`component_sources` 逐字段固定如下，不允许运行时按 donor 成绩改选：

| Genome 组件 | 固定来源 |
|---|---|
| `system_prompt` | P |
| `planning_policy` | D1 |
| `code_generation_policy` | D2 |
| `verification_policy` | D2 |
| `workflow_graph` | D1，整图原子继承 |

“整图继承”表示完整工作流图只来自 D1，不做节点级来源拼接，也不隐式换成主父代图。O3 的 `parent_ids`、主父代、组件来源、修改路径和内容 hash 必须与实际生成结果一致；重复或无变化 child 按现有算子失败规则记录，不伪造成功 lineage。

主要分析始终是 **child − primary parent**。仅 O3 的次要敏感性分析使用 `Q_child − max(Q_D1,Q_D2)`；两个 donor 的 Q 都必须可判定，否则该配对不可估计。donor best-of 不替换主分析，不进入稳定候选门槛。

### 3.3 同块条件与预算

同块 7 个 Episode 的任务、任务族、环境 seed、模型身份和 `EpisodeBudget` 完全相同。配置冻结的上限为：每 Episode 8 次模型调用、32768 输入 token、8192 输出 token、600 秒超时，每次调用最多重试 2 次；temperature 为 0.0，模型 seed 策略为与环境 seed 相同。若提供方不支持模型 seed，必须中止并报告，不得静默丢弃 seed。

当前 `model_id=e1-pilot-model-unpinned` 是明确表示尚未批准真实模型的占位符，不是可用模型名称。真实执行前必须由主 Agent 完成执行器集成并另行批准模型身份；任何替换都会改变配置和计划 hash，须重新冻结，不能在本协议下静默启动付费调用。

## 4. 事件顺序、pre-child state 与反泄漏

### 4.1 强制事件依赖

每块按以下顺序执行：

1. `p0`、`p1`、`p2`、`p3` 四个父代均完成评价并写入终态记录；
2. 只使用这四个父代的规范化输入构建 pre-child state，canonical 序列化并记录 `state_sha256`；
3. 每个 child 的生成事件同时依赖四个 `parent_evaluated` 事件和一个 `pre_child_state_serialized` 事件；
4. child 生成完成后才进行其评价。

即使某算子只使用一个或三个父代，也必须等待全部四个父代评价和 state 序列化。父代失败、超时或 Q 不可估计仍须写入终态和原因；不能用“跳过失败父代”代替依赖。任何 child score、child trajectory、child 生成状态、其他块或未来块输入均不得进入当前 state。机器计划用 `depends_on_episode_ids` 和 `depends_on_event_ids` 显式保存这些依赖。

### 4.2 父代规范化输入与任务状态六字段

状态解析器的纯函数输入是 `ParentEpisodeStateInput`：块号、父代 Episode ID、Genome hash、严格递增的 `ParentStateEvent`、终态 `run_status`、可空 `official_success`、可空官方逐测试列表以及进度不可判定原因。规范化事件只含 `step`、`dimension`、`outcome`、`source`、`error_type`；`source` 只允许 `trajectory` 或 `appworld_error`，失败事件必须有错误类型。禁止事后人工给轨迹贴状态标签。

| 任务状态字段 | 确定性映射 |
|---|---|
| `planning` | 该维度最后一个父代事件：`not_observed`（无事件）、`observed` 或 `failed` |
| `tool` | 同上；失败后的后续成功事件可恢复为 `observed` |
| `state_dependency` | 同上 |
| `code_execution` | 同上，代码/AppWorld 异常由规范化输入显式给出 |
| `task_incomplete` | `official_success=true/false` 分别为 `complete/incomplete`；若其未知，正常 `completed` 为 `unknown`，失败、超时或预算耗尽为 `incomplete` |
| `task_progress` | `value=官方非 no-op 目标测试通过数/非 no-op 目标测试总数`；不可判定时 `value=null` 且 `null_reason` 非空 |

`no_op` 标记必须来自官方评价的规范化结果，不能由 Agent 猜测。没有官方逐测试信息时使用调用方给出的具体原因；目标列表存在但无非 no-op 测试时固定为 `no_non_noop_target_tests`。不得用总分、成功布尔值或人工估计冒充通过比例，也不得用 child 信息填补 null。

### 4.3 种群状态五字段与哈希

| Population 字段 | 定义 |
|---|---|
| `mean` | 四个父代 Q 的算术均值 |
| `best` | 四个父代 Q 的最大值 |
| `variance` | 四个父代 Q 的总体方差，`ddof=0` |
| `genome_diversity` | 四个不同 Genome 内容 hash 的数量除以 4 |
| `stagnation` | 本 pilot 禁用历史停滞判断，始终为 `insufficient_history` |

任一父代 Q 为 null 时，`mean/best/variance` 全部为 null，并记录涉及哪些父代；不得只保留可用父代计算伪完整统计。Genome diversity 仍独立计算。不得根据两块或少量历史结果追加 `stagnant` 等事后标签。

pre-child canonical JSON 使用 UTF-8、对象键排序、紧凑分隔符并禁止 NaN，包含四个父代 ID/hash、六字段任务状态、五字段 population、null 原因和父代输入摘要。`state_sha256` 对不含该字段自身的 canonical bytes 计算；校验函数同时重算 population 指标和 hash。计划事件中的 `payload_sha256` 必须等于实际 state hash。

**接口验证边界：**当前已测试的是严格 schema、纯函数映射、事件依赖及合成输入下的反泄漏性质。AgentRunner 到该 schema 的适配器、真实 Trajectory 的 planning/tool 信号提取，以及 AppWorld 官方逐测试非 no-op 计数适配尚未集成或实测。不得把这些单元测试表述为真实 Agent/AppWorld 状态解析已经验证，也不以 112 个 Mock Episode 替代主 Agent 的执行器集成。

## 5. 预注册统计分析计划

### 5.1 分析单位、缺失与描述估计

每个算子有 16 个块内配对，三个 child 共享同块父代 control，因此不能把所有配对当作独立样本。主分析按 O1/O2/O3 分开，使用 child-primary 的 \(\Delta Q\)。任一配对所需 Q 为 null，该配对对该项估计记为不可估计并报告原因，不做均值填补、不改成最好成绩、不静默删任务。若某算子的任一预定块缺少可估计配对，该算子的主均值、主检验、Hedges 和稳定候选判定均为不可估计；可用配对只用于带覆盖数的描述，不替换预定的 16 块主样本。

报告逐任务、逐任务族、逐 seed、逐 Fold 和总体的配对数、不可估计数、\(\Delta Q\) 均值及分布。每个入选任务族只有 1 个任务变体，因此本样本中的族级结果只是描述，不能估计族内方差或宣称跨族泛化。

- **任务 cluster bootstrap 95% CI**：以 8 个任务为重采样单位，有放回抽取 8 个任务，保留被抽任务的全部 seed、算子和配对；重采样 10000 次，seed 固定 `20261201`，报告 percentile 95% CI。重采样样本无法计算时记为不可估计，不减少重采样次数或改换任务。
- **配对 Hedges \(g_{dz}\)**：对每算子 16 个块内差值计算 \(J\bar{\Delta}/s_\Delta\)，其中 \(s_\Delta\) 使用 `ddof=1`，\(J=1-3/(4(16-1)-1)\)。差值方差为零或有效配对不足时报告不可估计，不报告无穷大或强行记零；CI 使用上述任务 cluster bootstrap。
- **全样本检验与 Holm**：先求每算子的 8 个任务均值，再对任务整体符号翻转进行精确双侧置换检验；包含全部 \(2^8=256\) 种翻转和观察值本身，\(p=\#\{|T^*|\ge |T_{obs}|\}/256\)。对 O1/O2/O3 三个主检验做 Holm 校正。该小样本检验是 pilot 证据的一部分，不改变其非确认性定位。
- **O1 组件与 O2 操作分层**：四个 O1 目标和四个 O2 操作分别报告点估计、任务 cluster CI 和可估计数量；每项仅 4 块，均为次要诊断，不用于挑选后改主假设。

### 5.2 混合 logistic 与 operator×state

次要模型仅使用 48 个 child Episode，以官方 `success` 为二值响应，任务随机截距为 \(u_{task}\sim N(0,\tau^2)\)，seed 为固定效应，O1 为算子参考类：

\[
\operatorname{logit}P(Y_i=1)=\alpha+\beta Y^{parent}_i+\eta I(seed_i=200)
+\operatorname{operator}_i+\sum_k\gamma_kX^{parent}_{i,k}
+\sum_{o,k}\theta_{o,k}I(operator_i=o)X^{parent}_{i,k}+u_{task_i}.
\]

这里 \(Y^{parent}\) 是主父代官方 outcome，\(X^{parent}\) 是主父代的六字段任务状态，交互逐项预先声明为 `operator × state`，不根据显著性删减。类别水平使用本协议固定枚举；Q 缺失另设缺失指示，数值列的零占位只用于构造设计矩阵并必须与缺失指示同时出现，不能解释为真实 Q=0。

若随机效应奇异、完全/准完全分离、秩不足、优化不收敛或方差不可识别，逐项报告 `not_estimable` 和诊断，不通过删除不显著项、改任务、改 state 定义或反复更换估计器追求显著。父代 outcome 与其 `task_incomplete` 可能共线，48 个观测也不保证复杂交互可估计。

### 5.3 稳定候选、无信号与独立复现

某算子成为“稳定候选”必须同时满足：

1. seed=100 与 seed=200 的 \(\Delta Q\) 均值同号，Fold A 与 Fold B 的均值也同号，且四者方向一致；
2. `seed × Fold` 四个分层中至少 3 个 \(\Delta Q\) 点估计非零；这里的“非零”仅指未舍入点估计不等于零，不替代 CI 或显著性要求；
3. 全样本该算子的 Holm 校正 `p<0.05`。

满足门槛仍只获得后续独立验证资格。若效果只在同一任务族变体内复现，必须在另行批准的新任务族上独立复现；可使用此前保留的 dev，但启用时必须形成新协议，不能在查看 dev 后继续称其为独立验证。

若出现无信号，只允许报告预先定义的数据完整性、不可估计原因、算子失败、状态覆盖、方差和成本诊断。禁止为追求显著而调算子参数、换目标组件、改 seed、删任务、改模型/预算或重复挑选检验。任何实质修改都需要新协议和新的独立数据。

### 5.4 LOTO 预测诊断与成本

留一任务外（LOTO）以 8 个任务为外折：每次用 7 个任务的全部配对训练，预测被留出任务的 6 个 \(\Delta Q\)（2 seed × 3 operator）。固定使用 ridge 回归，`lambda=1.0`；特征只含预定 operator、seed、主父代 outcome 和六字段 pre-child state。类别使用固定 one-hot 水平，数值标准化和缺失指示只在训练折拟合，不在全数据预拟合，不依据 pilot outcome 调 lambda 或选特征。

- MAE：汇总全部 48 个留一预测；不可估计响应单独报告，不填补；
- Spearman：对 8 个任务的观察均值与对应折外预测均值计算秩相关；任一侧常数或有效任务不足时报告不可估计；
- LOTO 是任务外预测诊断，不是训练元策略，也不用于从 8 个任务中挑最好模型。

成本覆盖全部 112 Episode 及失败生成：按任务、块、算子报告输入/输出/总 token、调用、重试、wall time、生成成本、评价成本和总成本，并区分 `actual`、`estimated`、`unknown`。任何未知成本保持 null，不能写成 0；总计同时给出完整覆盖数。
