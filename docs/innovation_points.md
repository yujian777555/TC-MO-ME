# 拟检验创新点

## 1. 声明口径

本文列出 TC-MO-ME 的**拟检验研究创新**，不是已实现功能清单、文献新颖性证明或实验结论。是否在方法上区别于既有工作，仍需系统文献比较；是否有效，仍需按预注册式协议完成等预算、可复现的实验。

项目主线不是双层元演化，也不通过增加一层元参数演化来构造贡献。所有创新均围绕可审计轨迹、多目标配对信用和全生命周期成本展开。

## 2. 创新点一：任务轨迹与种群状态共同条件化的配对信用

对应 **RQ1**。

传统上只按算子累计即时成功率，会混合父代质量、任务难度、元策略选择和延迟效果。拟研究的方法把状态条件下的“算子—父代配对”作为信用单元，并显式记录元策略版本，同时读取：

- 任务轨迹中的规划、执行、异常、重试、验证和得分信息；
- 种群的多目标质量、多样性、世代及历史失败状态；
- 父代、子代、评价预算和后续谱系贡献。

拟形成的差异不是简单增加状态特征，而是把**配对选择、跨代信用与多目标结果**放入同一可追溯记录中，从而分别回答“哪个配对在何种状态下有效”和“收益是否延迟出现”。

该创新可被证伪：若轨迹或种群状态消融不影响等预算留出表现，或配对信用不比算子级/即时信用更稳定，则该主张不成立。E0 仅有轨迹、基因组、谱系与账本数据结构，尚未实现该元策略。

## 3. 创新点二：全生命周期成本约束下的多步元生产率

对应 **RQ2** 的成本与信用部分。

拟将候选生成、评价、失败和重试纳入同一个成本审计边界，用跨多个决策步骤的改进/成本比率描述搜索价值，而非仅以一次子代得分或一次 API 调用成本评价算子。其研究价值包括：

- 让“便宜但需多次修复”和“昂贵但一次成功”的候选进入可比较的等成本框架；
- 通过谱系追踪延迟贡献，避免短视信用只奖励即时高分；
- 显式保留未知成本、估算成本和实际成本，防止不完整记录制造虚假的高效率；
- 同时报告多目标变化与成本明细，避免单一分数隐藏权衡。

这是一项待验证的度量与归因设计，不表示当前 `total_cost` 已覆盖所有基础设施成本，也不表示多步信用算法已经实现。若结论对成本完整性、价格版本或时间范围高度敏感，则必须限制或否定该效率主张。

## 4. 创新点三：面向信息价值与不确定性的自适应评价预算

对应 **RQ2** 的预算分配部分。

拟研究的预算策略不只按当前分数分配评价次数，而是比较追加评价的预期信息价值与其成本，并显式处理候选被少评、停评或追加评价所造成的选择偏差。拟检验的核心是：在相同累计成本下，动态预算能否比均匀或固定预算更有效地识别值得保留的候选，同时不损害留出任务上的可信度。

该设计把评价次数视为搜索决策的一部分，并与多步信用共享成本记录。其实现必须保留预算分配理由、停止原因和未评价状态；最终比较仍需独立留出集，不能用反复自适应评价后的同一任务集证明泛化。

E0 只提供成本与用量字段，E1 只进行算子异质性 pilot；二者均不实现或验证自适应评价预算。

## 5. 创新点四：以数据契约保证上述研究可审计

支撑 **RQ1/RQ2**，但不把工程基础设施本身宣称为算法效果创新。

拟采用以下可检查约束支撑研究归因：

- 内容规范化哈希唯一标识 genome 的策略内容，身份和谱系元数据不改变内容哈希；
- lineage 同时记录全部父代、主父代、组件来源、修改路径与生成用量；
- episode 账本保留失败、零分、未知得分、重试、成本依据和产物哈希；
- 结果索引不内嵌原始轨迹，轨迹事件在记录时执行敏感信息脱敏；
- run 级来源信息绑定 Git 提交和配置哈希。

这些机制使配对信用与成本结论能够被复查，但只有后续实验才能判断研究假设是否成立。具体已实现行为见 `src/tc_mo_me/genome.py`、`src/tc_mo_me/model.py`、`src/tc_mo_me/ledger.py`、`src/tc_mo_me/trajectory.py`、`src/tc_mo_me/provenance.py` 和 [算法规范](algorithm_specification.md)。

## 6. 明确不列为当前创新的内容

- **跨任务迁移：PARKED。** 不启动、不评价、不宣称迁移或泛化优势；RQ3 的启动需独立批准。
- **双层元演化。** 不属于研究方案，不实现，也不以相关术语重新包装元策略。
- **E1 的完整算法验证。** E1 仅是算子异质性 pilot，不承担 RQ1/RQ2 的正式效果证明。
- **尚未测量的性能提升。** 当前不得声称更高任务成功率、更低成本、更好多样性、更快收敛或跨任务优势。
- **未经文献检索的“首次”或“领先”。** 本文不使用此类优先权表述。
